## 协作约定（用户与 AI 的分工，必须遵守）

- **用户手动写业务代码**（但会视心情临时让 AI 代写，如 Result/异常/Controller 曾让 AI 生成）。AI 默认角色是导师 + 评审：
  - 写之前：讲思路、设计、怎么下手
  - 写之后：按 code review 标准审代码，讲隐患和改进
  - 卡住 >2 小时：AI 帮定位和讲原理
  - Maven/Docker 配置样板、本文档类管理事务可代劳
- 项目相关一切产物写到 `D:\项目\ai客服项目\`，不写别处
- **接口测试一律优先用 Postman**（用户偏好：Windows Git Bash 终端发中文会踩 GBK 编码坑，Postman 统一 UTF-8 且可视化）。测 SSE 流式时若 Postman 不便，可用 `curl -N` 兜底
- **代码分工（重要）**：**后端业务代码由用户自己写**。AI **默认只给思路/设计（入参/出参/步骤/要用的 API/坑），不贴代码**；只有用户明确说"给我代码"时才提供。AI 负责评审用户写的代码与排错。**前端代码 AI 生成、用户评审**。

## 踩坑记录（面试素材，随做随记）

1. **主类包名拼错 `hepldesk` → 接口 404**：`@SpringBootApplication` 的 `@ComponentScan` 只扫描主类所在包及子包；所有业务类必须放在主类包正下方。已修正为 `com.example.helpdesk`。
2. **Spring Initializr 向导无 3.x 选项**：向导联网 start.spring.io（被墙）且默认只给最新 4.x；改用手动 Maven + pom 写死 parent `3.5.3` 走阿里云镜像解决。生态组件（MyBatis-Plus/Spring AI）对 4.x 适配未跟上，项目锁定 3.5.x。
3. **LF/CRLF 换行警告**：Windows 与 Git 换行符差异，无害；可用 `.gitattributes`（`* text=auto`）统一，暂未加。
4. **登录报"密码错误"真相**：`CommandLineRunner` 只在应用启动时执行一次，写完 DataInitializer 没彻底重启（热重载不算），导致占位密码没被替换。教训：加了"启动时初始化"类代码，必须完全停掉进程再全新启动。
5. **用 GET 访问 POST 接口**：浏览器地址栏发的是 GET，登录接口是 POST → 报 `HttpRequestMethodNotSupportedException`。用 Postman/curl 发 POST 即可。
6. **拦截器路径写 `/api/console/` 缺 `**`**：只匹配路径本身，子路径全裸奔 → `/me` 走了"无拦截"分支；又叠加 `Map.of` 不允许 null 值（UserContext 为空时 NPE）→ 500 系统繁忙。教训：`**` = 任意多层子路径；`Map.of` 的 value 不能是 null。
7. **404/405 被兜底成 500**：GlobalExceptionHandler 的 `Exception.class` 大网把 NoResourceFound 等请求错误也包装成"系统繁忙"。后续需补充专门 handler（低优先级）。
8. **前端报"网络错误"= 后端 8080 没启动**：axios 收不到任何响应时的兜底文案。排查顺序：先浏览器开 `localhost:8080/api/health` 确认后端活着，再看 F12 Console。
9. **跨域解法**：前端 vite 配 proxy 把 `/api` 转发到 8080，浏览器只见同源，OPTIONS 预检消失（后端拦截器放行 OPTIONS 的逻辑保留，上线后不用 vite 时会用到）。
10. **GLM 接入连环坑（已转 DeepSeek）**：① 没实名认证 → key 全 401；② Git Bash 终端发中文 → GBK 编码 → DeepSeek/GLM 报 400 UTF-8 错误（用 Postman 或英文测试）；③ Spring AI 默认在 base-url 后拼 `/v1/chat/completions`，GLM 只认 `/v4/` → 404，需配 `completions-path: /chat/completions`（这个属性是解 jar 翻 javap 挖出来的）；④ glm-4.7-flash 免费模型持续 1305 繁忙。DeepSeek 默认路径兼容、模型不挤，换之。`base-url: https://api.deepseek.com`，`model: deepseek-chat`。
11. **MySQL 8 连接报 `Public Key Retrieval is not allowed`**：caching_sha2_password + 非 SSL 连接需要公钥交换，JDBC URL 加 `allowPublicKeyRetrieval=true` 解决。
12. **IDEA 静态检查误报**："找不到 ChatClient Bean" 红字——Spring AI 自动配置只生成 `ChatClient.Builder`，需自建 `@Bean ChatClient chatClient(ChatClient.Builder)`（AiConfig）。
13. **SSE 前端三坑**：① 网络会把多个 token 打包到达，需前端"打字机节奏器"（队列 + 每 15ms 吐一字）平滑播放；② **Vue3 响应式坑**：对象 push 进 ref 数组后，局部变量仍指向原始对象，改它不触发渲染——必须通过 `messages.value[下标]` 改；③ Enter 发送 / Shift+Enter 换行用 `@keydown.enter.exact.prevent`。
14. **流式接口返回格式**：后端 SSE 事件协议为 `visitor`(回执 JSON) → `token`(逐字) → `done`(完整落库消息 JSON) / `error`；前端用 `fetch`（非 axios）+ `ReadableStream` 读取，SSE 帧按空行 `\n\n` 切分。
15. **云服务器踩坑（腾讯云 Ubuntu 26.04）**：① `get.docker.com`/`get.daocloud.io` 全部连不上（出站被过滤）→ 用**阿里云 docker-ce apt 源**（`noble` 套件，26.04 也可用）；② **FinalShell 多行粘贴不可靠**：heredoc(`<<'EOF'`) 两次都没写进文件，长命令也易截断 → 一律用**单行命令**；③ Docker Hub 直连卡死 → 配 `/etc/docker/daemon.json` 镜像加速（可用：`mirror.ccs.tencentyun.com`、`docker.m.daocloud.io`；`mirror.baidubce.com` 不通）；④ ES 需 `vm.max_map_count=262144`；⑤ **ES 启动要 1-3 分钟**，期间 curl 会 `Connection reset by peer`（端口代理已监听但 HTTP 未就绪），等够再测；⑥ ES 关了认证（`xpack.security.enabled=false`），**9200 绝不能裸开公网**，本地后端走 SSH 隧道或安全组限 IP。
16. **写 ES 报 `Connection refused` = SSH 隧道断了**（FinalShell 断开重连/休眠/切网都会发生）。注意：向量化走公网（不受影响），只有走隧道的 ES 操作失败 → 报错落在 `writeToEs`。**习惯：开工先 `curl http://localhost:9200` 自检隧道**。
17. **双写不一致首次现身**：顺序是"先写 MySQL 再写 ES"，ES 失败后 MySQL 留下孤儿 `kb_chunk` 且文档状态为 FAILED。W7/W11 处理（失败重试、清理、对账补偿）。
18. **SLF4J 占位符**：`log.error("id=", doc.getId(), e)` 不会填值，必须 `log.error("id={}", doc.getId(), e)`；最后一个参数是 Throwable 时会自动打堆栈。
19. **ES 客户端 API 心法**：Java 客户端看不懂时，先把它翻译回 curl（`esClient.index(...)` = `PUT /索引/_doc/{id}`），对照表见对话记录。
